# 프로젝트 문서 자산화 설계

## 목적

`메이플 환산 아이템메이커 브릿지`의 코드와 제품 문서를 같은 버전 관리 체계에서 유지한다. 개발자·포트폴리오 독자, 실제 사용자, 블로그 독자가 각각 필요한 정보를 빠르게 얻도록 문서의 목적과 깊이를 분리한다.

## 문서 경계

- 루트 `README.md`는 개발자와 포트폴리오 독자를 위한 짧은 진입점이다. 문제 정의, 해결 방식, 핵심 기술, 검증, 문서 링크만 담는다.
- `docs/gitbook/`은 사용자를 위한 제품 문서의 Markdown 원본이다. GitBook에는 이 파일을 옮겨 게시한다.
- `docs/blog/`은 이 프로젝트에 한정된 블로그 게시용 회고 원고의 초안이다. 개인적인 일기나 범용적인 글은 포함하지 않는다.
- `docs/assets/screenshots/`는 제품 문서와 회고에서 사용하는 스크린샷 및 촬영 체크리스트만 보관한다.
- 소스 코드와 테스트는 기존 `src/`, `test/` 구조를 유지한다. 문서 자산은 코드와 분리된 `docs/` 아래에만 추가한다.

이 구조는 코드와 사용자 문서가 같은 릴리스에서 바뀌도록 하되, 루트 디렉터리가 자료 모음처럼 보이는 일을 막는다.

### GitHub README

README는 다음 순서로 구성한다.

1. 프로젝트 한 줄 소개와 해결하는 반복 작업
2. 경매장 찜 목록 내보내기, 환산기 장비 보관, 스펙업 순서 분석의 핵심 기능
3. Chrome Extension Manifest V3, 콘텐츠 스크립트, `chrome.storage.local`, 환산기 로컬 저장소 주입, Jest 테스트의 기술적 포인트
4. 설치/사용 가이드와 블로그 회고로 연결하는 링크
5. 면책 조항 및 라이선스

README는 상세한 사용 절차나 긴 회고를 반복하지 않는다.

### GitBook 사용자 가이드

사용자가 수행하려는 작업을 기준으로 다음 문서를 제공한다.

| 문서 | 독자의 목표 | 포함 내용 |
| --- | --- | --- |
| `getting-started.md` | 확장 프로그램을 설치하고 준비한다 | 압축 해제 확장 프로그램 로드, 필요한 사이트와 권한, 사전 조건 |
| `auction-to-item-maker.md` | 경매장 찜 목록을 환산기에 추가한다 | 찜 목록 방문, 목록 선택/정리, 환산기 주입, 결과 확인 |
| `storage.md` | 캐릭터별 장비 세트를 저장·적용한다 | 내 장비/보관함 불러오기, 폴더 생성, 선택 저장, 교체 시 경고 |
| `spec-order.md` | 투자 우선순위를 분석한다 | 환산기에서 데이터 조회, 목표 최종뎀·교환불가 가중치·조각/환불 가격 설정, 결과 해석 |
| `troubleshooting.md` | 실패와 제약을 해결·이해한다 | 사이트 UI 변경 가능성, 지원 범위, 데이터 덮어쓰기 주의, 점검 순서, 면책 |

각 작업 문서는 목표, 사전 조건, 단계, 성공 확인, 주의 사항, 문제 해결 링크의 순서를 따른다. 스크린샷은 해당 단계 바로 다음에 배치하며, 이미지가 없어도 절차가 이해되도록 본문만으로 완결한다.

### 블로그 회고 초안

블로그 글은 게시 가능한 서사형 원고로 작성한다. 제목은 게시 시 조정할 수 있으나, 본문은 다음 흐름을 따른다.

1. 반복적인 경매장 비교와 환산 시뮬레이션이라는 문제
2. 브라우저 확장으로 경매장과 환산기를 연결한 해결 방향
3. 외부 서비스 사이의 데이터 형식 변환과 안정적인 주입 설계
4. 단방향 내보내기에서 보관함·캐릭터 장비 가져오기·스펙업 순서 분석으로 확장한 과정
5. 테스트와 사용자 확인 흐름으로 신뢰성을 확보하려 한 선택
6. 외부 사이트 변경에 대한 제약, 향후 개선점, 배운 점

모든 기술 주장은 저장소의 구현과 테스트로 확인 가능한 범위에서만 작성한다. 외부 서비스와 무관한 개인 프로젝트라는 면책도 포함한다.

## 스크린샷 계획

스크린샷 파일명과 촬영 시점을 `docs/assets/screenshots/README.md`에 기록한다. 최초 촬영 대상은 다음과 같다.

1. Chrome 확장 프로그램 관리 화면의 개발자 모드와 압축 해제 확장 프로그램 로드 지점
2. 팝업의 `경매장 찜 목록` 탭과 선택·내보내기 동작
3. 팝업의 `환산 메이커 보관함` 탭과 폴더/장비 보관 흐름
4. 팝업의 `스펙업 순서` 탭과 분석 설정 및 결과
5. 환산기 아이템메이커에서 주입 결과를 확인하는 화면

스크린샷에는 개인 캐릭터명, 계정 정보, 민감하거나 공유하기 어려운 거래 정보가 보이지 않도록 마스킹한다.

## 유지보수 규칙

- 사용자에게 보이는 기능·설치 방법·권한·제약이 바뀌면 같은 변경에서 해당 GitBook 원본을 갱신한다.
- 새 기능은 `product-overview.md`, README 요약, 해당 작업 가이드 중 필요한 범위만 갱신한다.
- 블로그 초안은 릴리스 노트가 아니다. 완성된 변경의 맥락과 배움을 정리할 때만 갱신한다.
- GitBook으로 옮긴 뒤에도 Markdown 원본은 이 저장소에 남긴다.

## 검증 기준

- README의 기능 설명은 `manifest.json`과 `src/`의 현재 UI·동작과 일치한다.
- 모든 GitBook 작업 가이드는 사전 조건부터 성공 확인까지 독립적으로 따라 할 수 있다.
- 위험한 동작(환산기 데이터 교체, 외부 사이트 의존성)은 가이드와 문제 해결 문서에 명시한다.
- 블로그 글은 과장된 성과 주장 없이 구현 근거와 실제 트레이드오프를 설명한다.
